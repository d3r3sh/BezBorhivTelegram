## Технічні вимоги (з SRS, дублюю критичне)

- **Стек:** Swift 5.10+, SwiftUI, SwiftData, iOS 17.0+ minimum deployment target, тільки iPhone, портретна орієнтація
- **Архітектура:** MVVM. View → ViewModel (`@Observable`) → Services. Бізнес-логіка ізольована від UI та БД
- **Всі грошові розрахунки — тільки `Decimal`**, ніколи Double/Float. Округлення half-up до 2 знаків
- **Модель даних — CloudKit-ready з першого дня** (розділ 6.2 SRS): без `@Attribute(.unique)`, всі relationships optional, всі поля з дефолтами або optional, ідентифікатори UUID
- **Single source of truth** — фактична історія платежів (`Payment`). Графік обчислюється on-the-fly. Поточний залишок = `LoanCalculator.balance(from: initialAmount, ...)` через всю послідовність платежів
- **`paymentDay` зберігається окремо** від `firstPaymentDate`. При перерахунку графіка після лютого передавати `paymentDay` явно в `generateSchedule`, щоб березень повертався до 31-го, а не залишався на 28-му
- **Дати** — локальна таймзона пристрою, порівняння на рівні календарного дня, без UTC-перетворень
- **UI-мова:** українська
- **Нотифікації:** локальні (UserNotifications), без сервера. Час — 10:00. Перепланувати після **будь-якої** операції (платіж, редагування, архівація). Дата нотифікації — від реальної наступної дати платежу, не від `firstPaymentDate`
- **Мережевих запитів немає взагалі.** Дані тільки локально
- **Числовий формат:** пробіл (non-breaking space `\u{00A0}`) між тисячами, кома для копійок. Поле ставки — тільки нормалізація десяткового роздільника (без групування тисяч)

## Ключові архітектурні рішення (з досвіду реалізації)

- `Loan.sortedActualPayments() -> [ActualPayment]` і `Loan.currentBalance() -> Decimal` — спільні хелпери на рівні моделі, усувають дублювання в 5+ місцях
- `HomeViewModel.buildScheduleMap(for: [Loan]) -> [UUID: [ScheduledPayment]]` — один O(N) прохід для всіх per-loan даних; уникай N log N перерахунків при сортуванні
- `StrategyPlanner.simulateMonths`: звільнений платіж після закриття кредиту додавати до бюджету **наступного місяця** (`freedNextMonth`), не поточного
- `NotificationScheduler.rescheduleAllFromContext(_ context: ModelContext)` — єдина точка входу; викликати після кожного `context.save()` в будь-якому ViewModel
- Лічильник «N з M платежів» у картці кредиту: M = `paidCount + remainingSchedule.count` (актуальний після дострокових погашень)
- «Залишилось 0 платежів» → показувати «виплачено 100%», не «залишилось 0»

## Порядок роботи (майлстоуни)

Після кожного майлстоуна — зупинись, покажи що зроблено, дочекайся ОК.

**M1 — Ядро розрахунків:**
- `LoanCalculator`: ануїтет (4.1), коригування останнього платежу (4.2), IRR (4.3), перерахунок (4.4), дати 29/30/31 з явним `paymentDay` (4.5)
- Unit-тести TC-CALC-01…TC-CALC-14. Тести мають проходити: `xcodebuild test`
- Deployment target тест-таргету = deployment target основного таргету

**M2 — Модель даних і сховище:**
- SwiftData-моделі `Loan` + `Loan.sortedActualPayments()` / `Loan.currentBalance()`, `Payment`, `AppSettings`
- Service layer: `LoanService`, `PaymentService`, `AppSettingsService`
- Тести на persistence (CRUD, cascade delete)

**M3 — Кредити CRUD + головний екран:**
- Додавання: 2 режими, сценарій «вже виплачується», розстрочка 0%, правильні лейбли (FR-LOAN-C-7)
- Редагування + видалення з підтвердженням
- HomeView з `buildScheduleMap`, сортування, картки, порожній стан, банер стратегії

**M4 — Платежі + прострочення + архів:**
- Фіксація, переплата/недоплата, позаплановий, backdating, редагування/видалення з перерахунком
- Прострочення: статус наступного дня, червона картка
- Архів: пропозиція при 0, список з деталями/розархів/видалення (FR-ARCH-2 — всі три дії)

**M5 — Стратегія і бюджет:**
- `StrategyPlanner` з правильним `simulateMonths` (freed → наступний місяць)
- Drag & drop для «Свій порядок» у результуючому екрані (List + `.onMove` + `editMode`)
- Рекомендована сума від поточного `loan.currentBalance()`, не `initialAmount`
- Нотифікації від реальної наступної дати, `rescheduleAllFromContext` після кожної операції

**M6 — Нотифікації, налаштування, онбординг:**
- `NotificationScheduler.rescheduleAllFromContext` + `notificationData(for:)`
- Онбординг 3 слайди; слайд 1 — заголовок «Що вміє цей додаток»
- Налаштування з debug-секцією «Очистити всі кредити» (`#if DEBUG`)

**M7 — Фінал:**
- Smoke-чекліст із 14 пунктів
- Іконка; README з інструкцією збирання
