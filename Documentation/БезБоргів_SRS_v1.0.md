## 2. Терміни та визначення

| Термін | Визначення |
|---|---|
| Кредит | Боргове зобов'язання користувача з графіком щомісячних платежів |
| Ануїтетний платіж | Однакова щомісячна сума; частка відсотків зменшується, частка тіла зростає |
| Розстрочка 0% | Кредит без відсотків: сума платежу × кількість платежів = сума кредиту |
| Тіло кредиту | Основна сума боргу без відсотків |
| Залишок | Поточна сума тіла кредиту, яку ще треба сплатити |
| Плановий платіж | Платіж за графіком (дата + сума) |
| Позаплановий платіж | Додаткова сума, внесена в будь-який день понад графік (дострокове погашення) |
| Прострочений платіж | Плановий платіж, не відмічений як оплачений, дата якого минула (статус з наступного дня) |
| Бюджет | Загальна сума на місяць, яку користувач готовий виділяти на всі кредити (включно з обов'язковими платежами) |
| Стратегія погашення | Правило розподілу вільного залишку бюджету: «Лавина», «Сніжний ком» або ручний пріоритет |

## 3. Функціональні вимоги

### 3.1 Онбординг (FR-ONB)

- **FR-ONB-1.** При першому запуску показуються 3 екрани онбордингу:
  1. «Відслідковуй всі кредити в одному місці»
  2. «Отримуй нагадування про платежі»
  3. «Обери стратегію і закрий борги швидше»
- **FR-ONB-2.** Онбординг можна пропустити (кнопка «Пропустити») та пройти до кінця (кнопка «Далі» / «Почати»).
- **FR-ONB-3.** Онбординг показується лише один раз (прапорець у локальних налаштуваннях).
- **FR-ONB-4.** Після онбордингу запитується дозвіл на push-нотифікації (системний діалог iOS).

### 3.2 Кредити: створення (FR-LOAN-C)

- **FR-LOAN-C-1.** Кредит створюється в одному з двох сценаріїв:
  - **Новий кредит** — користувач щойно взяв кредит;
  - **Кредит, що вже виплачується** — вводиться поточний залишок і кількість платежів, що залишились (без введення історії).
- **FR-LOAN-C-2.** Два режими введення даних (перемикач):
  - **«Я знаю ставку»** — застосунок розраховує суму щомісячного платежу (формула ануїтету, п. 4.1);
  - **«Я знаю суму платежу»** — застосунок розраховує річну ставку (IRR, п. 4.3). Якщо `платіж × кількість платежів = сума кредиту` → розстрочка 0%.
- **FR-LOAN-C-3.** Ставка 0% дозволена (оплата частинами українських банків).
- **FR-LOAN-C-4.** Поля кредиту:

| Поле | Обов'язкове | Примітка |
|---|---|---|
| Назва | Так | Довільний текст, задає користувач |
| Сума кредиту / поточний залишок | Так | > 0, грн з копійками |
| Кількість платежів (що залишились) | Так | Ціле число > 0 |
| Річна ставка, % | Так у режимі «Я знаю ставку» | 0% дозволено |
| Сума щомісячного платежу | Так у режимі «Я знаю суму платежу» | грн з копійками |
| Дата першого (наступного) платежу | Так | Задає день платежу для всього графіка |

- **FR-LOAN-C-5.** Валідація адекватності значень (діапазони ставок тощо) у v1 не виконується. Базові технічні перевірки (число > 0, поле не порожнє) — виконуються.
- **FR-LOAN-C-6.** Після збереження автоматично генерується графік платежів (п. 3.3).
- **FR-LOAN-C-7.** Підписи полів залежать від сценарію.
  - **Кількість платежів:** у режимі **«Вже плачу»** — **«Платежів залишилось»** з підказкою «Скільки щомісячних платежів вам ще залишилось внести»; у режимі **«Новий»** — **«Платежів»** без підказки.
  - **Дата платежу:** у режимі **«Вже плачу»** — **«Наступний платіж»** з підказкою «Дата найближчого платежу, який вам ще треба внести»; у режимі **«Новий»** — **«Перший платіж»** без підказки.

### 3.3 Графік платежів (FR-SCHED)

- **FR-SCHED-1.** Графік — це перелік планових платежів: №, дата, сума, частка тіла, частка відсотків, залишок після платежу, статус.
- **FR-SCHED-2.** Періодичність — тільки щомісяця.
- **FR-SCHED-3.** День платежу — число з дати першого платежу. Якщо в місяці менше днів (29/30/31 → лютий тощо), платіж призначається на **останній день місяця** (поведінка банків). **Важливо:** після перерахунку графіка день платежу (paymentDay) зберігається як оригінальне значення (не замінюється числом дати clamped-місяця).
- **FR-SCHED-4.** Усі суми — з точністю до копійок (2 знаки), стандартне математичне округлення.
- **FR-SCHED-5.** **Останній платіж коригується** так, щоб залишок після нього дорівнював рівно 0,00 грн (компенсація накопиченого округлення).

### 3.4 Кредити: редагування, видалення, архів (FR-LOAN-E)

- **FR-LOAN-E-1.** Кредит можна редагувати після створення (у т.ч. ставку). Після збереження змін графік майбутніх платежів **повністю перераховується** під нові дані; вже внесені платежі не змінюються.
- **FR-LOAN-E-2.** Повне видалення кредиту дозволене, тільки з діалогом підтвердження. Видаляється кредит разом з історією платежів, незворотно.
- **FR-LOAN-E-3.** Коли залишок кредиту досягає 0,00 грн, застосунок **пропонує архівувати** кредит (діалог). Автоматична архівація не виконується.
- **FR-LOAN-E-4.** Архівовані кредити доступні на окремому екрані «Архів», не показуються на головному екрані та не враховуються в сумарних цифрах і плані погашення.
- **FR-LOAN-E-5.** Кредит можна розархівувати; він повертається до активних із поточним станом.

### 3.5 Платежі (FR-PAY)

- **FR-PAY-1.** Платіж фіксується **тільки вручну** (кнопка «Оплачено» біля планового платежу).
- **FR-PAY-2.** При фіксації за замовчуванням підставляється **планова (мінімальна)** сума. Якщо стратегію обрано і для цього кредиту **рекомендований платіж більший за мінімальний** (кредит пріоритетний за стратегією) — за замовчуванням підставляється **рекомендована** сума (мінімальний + додаткова частина за стратегією), і показуються **дві кнопки-підказки**: «Підставити [рекомендована] ₴» та «Мінімальний [мінімальна] ₴». Для кредитів, де рекомендований = мінімальному (або стратегію не обрано), показується **одна** кнопка-підказка з мінімальним платежем. Усі кнопки лише підставляють значення; ручне редагування (недоплата/переплата) збережено. Фактична сума зберігається окремо від планової.
- **FR-PAY-3.** Дату платежу можна вказати заднім числом.
- **FR-PAY-4.** **Позаплановий платіж**: окрема кнопка «Внести додаткову суму» — будь-яка сума в будь-який день. Зменшує тіло кредиту.
- **FR-PAY-5.** Дострокове погашення (позаплановий платіж або переплата) **зменшує залишок і скорочує термін**. Кількість платежів зменшується, коли внесена сума перевищує тіло одного або кількох майбутніх платежів. При малих переплатах кількість платежів може лишатися незмінною — зменшується лише останній платіж. Сума щомісячного платежу **не змінюється** в будь-якому разі. Графік перераховується (п. 4.4).
- **FR-PAY-6.** Після будь-якої фіксації платежу (планового, позапланового, з переплатою/недоплатою) залишок і графік майбутніх платежів перераховуються.
- **FR-PAY-7.** Внесений платіж можна відредагувати або видалити. Після цього залишок і весь графік наперед перераховуються.
- **FR-PAY-8.** Історія платежів зберігається і відображається в деталях кредиту (дата, сума, тип: плановий/позаплановий).

### 3.6 Прострочення (FR-DUE)

- **FR-DUE-1.** Плановий платіж отримує статус «Прострочено» **наступного дня** після дати платежу, якщо не відмічений як оплачений.
- **FR-DUE-2.** Пеня не розраховується — тільки статус.
- **FR-DUE-3.** Кредит із простроченим платежем на головному екрані виділяється **червоним кольором + бейджем**.
- **FR-DUE-4.** Після фіксації простроченого платежу статус знімається.

### 3.7 Головний екран (FR-MAIN)

- **FR-MAIN-1.** Сумарний блок зверху (коралова плашка):
  - Загальна сума боргу по всіх активних кредитах;
  - **«Мінімальні платежі на місяць»** — сума обов'язкових (планових) платежів по всіх активних кредитах;
  - **«Рекомендовані платежі на місяць»** — мінімальні платежі + вільний залишок бюджету, спрямований за обраною стратегією (дорівнює бюджету, коли той більший за мінімальні). Рядок показується **лише** коли стратегію обрано **і** бюджет задано та більший за мінімальні платежі; інакше рядок ховається і показуються тільки мінімальні.
- **FR-MAIN-2.** Список активних кредитів, відсортований **за датою наступного платежу** (найближчий — зверху).
- **FR-MAIN-3.** Картка кредиту в списку: назва (одним рядком), **загальний борг** (тіло + залишок відсотків = сума всіх майбутніх платежів за графіком — та сама цифра, що на екрані деталей кредиту), сума наступного платежу **і дата наступного платежу поряд із сумою** (напр. «5 287,11 ₴ · 30 серп»), лічильник платежів («N з M платежів», де M — поточна загальна кількість з урахуванням дострокових погашень), **прогрес-бар** (% виплаченого тіла).
- **FR-MAIN-4.** Якщо стратегія погашення не обрана — на головному екрані показується **банер «Оберіть стратегію погашення»**, що веде на вкладку «План». Банер видно, поки стратегію не обрано; після вибору зникає.
- **FR-MAIN-5.** Порожній стан (немає кредитів): ілюстрація + кнопка «Додати перший кредит».
- **FR-MAIN-6.** Тап по картці → екран деталей кредиту.
- **FR-MAIN-7.** Під сумарною плашкою окремим блоком показується **«Залишилось цього місяця»**:
  - Базова сума = **мінімальні** платежі на місяць (сума обов'язкових платежів по всіх активних кредитах, чий наступний платіж припадає на поточний місяць або прострочений). Рекомендований бюджет і стратегія на цей блок **не впливають** — вони є підказкою на екрані «План»;
  - Залишок = сума `max(0, monthlyPayment − paidThisPeriod)` по кожному такому кредиту, де `paidThisPeriod` — усі платежі (і планові, і позапланові), внесені в поточному платіжному періоді кредиту;
  - Оновлюється після кожного внесеного платежу; на початку кожного календарного місяця автоматично скидається;
  - Коли залишок ≤ 0 — показується **«Цього місяця все внесено»** (без від'ємних чисел).
- **FR-MAIN-8.** Тап на кораловий сумарний блок («Загальний борг») → відкриває екран «Загальний борг» (п. 3.13). Якщо активних кредитів немає — тап ігнорується.

### 3.8 Деталі кредиту (FR-DET)

- **FR-DET-1.** Показуються: назва, залишок тіла кредиту, прогрес-бар, сума й дата наступного платежу, кількість платежів що залишились (актуальна, з урахуванням дострокових погашень). Якщо залишок = 0 — показується «виплачено 100%».
- **FR-DET-2.** **Таб «Графік платежів»** (обирається за замовчуванням): повний графік платежів (п. 3.3) зі статусами: майбутній / оплачено / прострочено. За замовчуванням показуються перші 6 рядків; кнопка «Показати всі N» розгортає повний список. Поведінка без змін порівняно з попередньою реалізацією.
- **FR-DET-3.** **Таб «Фактичні оплати»**: список фактично внесених платежів — зміст рядка і дії описані у FR-DET-7–FR-DET-10.
- **FR-DET-4.** Дії: «Оплачено» (для чергового платежу), «+ Додатково», «Дострокове погашення», «Редагувати кредит», «Архівувати», «Видалити».
- **FR-DET-5.** Блок прогнозу закриття (п. 3.15) показується одразу після прогрес-бару і рядка з кількістю платежів.
- **FR-DET-6.** Перемикач табів: два toggle-кнопки («Графік платежів» | «Фактичні оплати»), стиль — neumorphic сегмент-контрол у стилі дизайн-системи, розміщені безпосередньо над списком. Перемикач показується завжди, незалежно від наявності фактичних платежів.
- **FR-DET-7.** Рядок у табі «Фактичні оплати»: дата фактичної оплати (`actualDate`); сума (`actualAmount`); тип («Плановий» / «Додатковий»); різниця з планом (FR-DET-8). Сортування: хронологічно за `actualDate`, найстаріший зверху.
- **FR-DET-8.** Різниця з планом: `diff = actualAmount − plannedAmount` (де `plannedAmount` — значення зі збереженого `Payment.plannedAmount`). `diff > 0` → зеленим «+[diff] ₴»; `diff < 0` → червоним «−[|diff|] ₴» (знак − у префіксі, не у числі); `diff = 0` або `plannedAmount = 0` → не відображати. Для `isExtra = true`: різницю не рахувати, показати мітку «Додатковий».
- **FR-DET-9.** Дії у табі «Фактичні оплати»: тап на рядок → редагування (сума, дата) через `RecordPaymentView` (FR-PAY-7); свайп вліво → кнопка «Видалити» з діалогом підтвердження (FR-PAY-7). Після будь-якої дії залишок і графік перераховуються (FR-PAY-6, FR-PAY-7).
- **FR-DET-10.** Порожній стан таба «Фактичні оплати»: якщо фактичних платежів немає — по центру текст «Ще немає оплат». Перемикач табів видно завжди.

### 3.9 Бюджет і стратегія погашення (FR-STRAT)

- **FR-STRAT-1.** Вибір стратегії — **опціональний** (застосунок працює як трекер і без неї), але головний екран показує банер-нагадування (FR-MAIN-4).
- **FR-STRAT-2.** Бюджет — **опціональний**. Вводиться загальна сума на місяць **включно** з обов'язковими платежами.
- **FR-STRAT-3.** Стратегії (на екрані вибору кожна пояснена простими словами):
  - **«Лавина» (рекомендована, підсвічена)** — вільний залишок спрямовується на кредит із найбільшою ставкою;
  - **«Сніжний ком»** — вільний залишок спрямовується на кредит із найменшим залишком.
- **FR-STRAT-4.** Якщо бюджет введено і він **більший** за суму обов'язкових платежів: план показує рекомендацію «внести додатково N грн на кредит X» (пріоритетний за стратегією). Рекомендація — тільки підказка; платіж користувач фіксує вручну.
- **FR-STRAT-5.** Якщо бюджет **менший** за суму обов'язкових платежів — перехід до результату **не блокується**; у плані показується м'яке попередження («Бюджет менший за обов'язкові платежі: N грн») і **немає рекомендацій** додаткових платежів (лише обов'язкові).
- **FR-STRAT-6.** Якщо бюджет не введено або дорівнює обов'язковим платежам — стратегія визначає лише порядок пріоритету кредитів, без рекомендацій додаткових платежів.
- **FR-STRAT-7.** Екран плану показує на місяць: «плати X грн на кредит А, Y грн на кредит Б, …» (обов'язкові платежі + рекомендований додатковий). Рекомендований додатковий платіж для пріоритетного кредиту пропонується також на екрані фіксації платежу (FR-PAY-2). Розрахунок ведеться від **поточного залишку** кредиту (з урахуванням внесених платежів), а не від початкової суми.
- **FR-STRAT-8.** **Ефект стратегії**: «З цією стратегією ви закриєте всі кредити на N місяців раніше» (порівняння: графіки без додаткових платежів vs з додатковими за стратегією). Поруч з «N місяців раніше» показується абсолютна дата закриття **всіх** кредитів за стратегією у форматі п. 4.7.
- **FR-STRAT-9.** План **автоматично перебудовується** після: фіксації/редагування/видалення будь-якого платежу, дострокового погашення, додавання/редагування/видалення/архівації/розархівації кредиту, зміни бюджету чи стратегії.
- **FR-STRAT-10.** Бюджет і стратегію можна змінити будь-коли в Налаштуваннях.
- **FR-STRAT-11.** Вкладка «План» має **4 стани**:
  - **Стан 1 — онбординг-попап.** Показується при першому вході або доки стратегію не обрано. Якщо є ≥ 1 активний кредит — кнопки **«Обрати план»** і **«Додати кредит»**; якщо кредитів немає — **лише «Додати кредит»**. «Обрати план» → Стан 2.
  - **Стан 2 — введення бюджету.** «Скільки ви готові виділяти на місяць на кредити?», показ мінімального (обов'язкового) платежу і вільного залишку, поле вводу + **«Підрахувати план»** → Стан 3.
  - **Стан 3 — завантаження.** Анімація «Підбираємо оптимальну стратегію…» 2 сек → Стан 4.
  - **Стан 4 — результат.** Готовий план. За замовчуванням обрана **«Лавина»** з бейджем «Рекомендовано»; можна перемкнути на «Сніжний ком». Показуються ефект «на N місяців раніше» і розподіл «Цього місяця». Кнопки **«Змінити бюджет»** і **«Обрати іншу стратегію»** повертають до Стану 2.
  - **Повторний вхід:** якщо стратегію вже обрано — одразу Стан 4.
- **FR-STRAT-12.** Бейдж «Рекомендовано» показується **лише** біля стратегії «Лавина».

### 3.10 Нотифікації (FR-NOTIF)

- **FR-NOTIF-1.** Локальні push-нотифікації про наступний платіж. Налаштування **глобальне** для всіх кредитів: незалежні перемикачі «за 3 дні», «за 1 день», «в день платежу».
- **FR-NOTIF-2.** Час надсилання — **10:00** локального часу пристрою (фіксовано).
- **FR-NOTIF-3.** Нагадування про прострочення — **щодня о 10:00**, поки платіж не буде зафіксовано.
- **FR-NOTIF-4.** Текст нотифікації містить назву кредиту та суму платежу. Приклад: «Завтра платіж 4 500,00 грн — "Кредит на авто"».
- **FR-NOTIF-5.** Якщо дозвіл на нотифікації не надано — застосунок працює без нагадувань; у Налаштуваннях показується підказка «Увімкніть нотифікації в Налаштуваннях iOS» з переходом у системні налаштування.
- **FR-NOTIF-6.** Нотифікації переплановуються після **будь-якої** зміни графіків: внесення/редагування/видалення платежу, дострокового погашення, створення/редагування/видалення/архівації/розархівації кредиту. Дата нотифікації обчислюється від **реальної наступної дати платежу** (не від `firstPaymentDate`).

### 3.11 Налаштування (FR-SET)

Склад екрана:
1. Нагадування: перемикачі «за 3 дні», «за 1 день», «в день платежу»;
2. Бюджет на місяць (грн);
3. Стратегія погашення;
4. Посилання на Privacy Policy.

### 3.12 Архів (FR-ARCH)

- **FR-ARCH-1.** Список архівованих кредитів: назва, загальна виплачена сума, дата закриття.
- **FR-ARCH-2.** Дії на кожному кредиті в Архіві:
  - **Переглянути деталі** (тап по рядку) → sheet з повним `LoanDetailView` у read-only режимі (кнопки дій задизаблені для архівованих);
  - **Розархівувати** (свайп вліво → кнопка «Відновити») — повертає до активних;
  - **Видалити** (свайп вліво → кнопка «Видалити», з діалогом підтвердження) — незворотно, разом з усією історією платежів.

### 3.13 Екран «Загальний борг» (FR-DEBT)

- **FR-DEBT-1.** Відкривається push-навігацією з головного екрану (FR-MAIN-8). Кнопка ← і заголовок реалізовані у view body, не в `.toolbar` (уникнення iOS 26 glass capsule artifact).
- **FR-DEBT-2.** Вміст екрана:
  - **«Загальний борг»** — сума `loan.currentBalance()` по всіх активних кредитах (тіло без відсотків);
  - **«Усього внесено»** — сума всіх `actualAmount` по всіх `Payment` активних кредитів;
  - **Блок «Дата закриття»** — відповідно до FR-DEBT-3;
  - **Кнопка «Календар платежів»** → екран FR-CAL (п. 3.14).
- **FR-DEBT-3.** Логіка блоку «Дата закриття всіх кредитів»:
  - Стратегія обрана (будь-яка) → показати дату закриття всіх кредитів за стратегією у форматі п. 4.7;
  - Стратегія НЕ обрана І активних кредитів > 1 → банер «Оберіть стратегію, щоб побачити, коли закриєте кредити раніше» (посилання на вкладку «План»);
  - Стратегія НЕ обрана І активний кредит рівно 1 І бюджет заданий і більший за мінімальний платіж → показати дату закриття з урахуванням extra = budget − minPayment, спрямованого на єдиний кредит (п. 4.7);
  - Стратегія НЕ обрана І активний кредит рівно 1 І бюджет не заданий або ≤ мінімальному → показати дату за графіком (`schedule.last?.date`).

### 3.14 Календар платежів (FR-CAL)

- **FR-CAL-1.** Відкривається з кнопки на екрані «Загальний борг». Push-навігація з кнопкою ←, реалізованою у view body.
- **FR-CAL-2.** Сітка:
  - Два місяці показуються **поруч горизонтально** (2 колонки): ліва = раніший місяць пари, права = наступний. Горизонтальний пейджинг — кожен свайп/сторінка = нова пара місяців;
  - Мінімальна видима пара починається з поточного місяця. Перехід назад — неможливий;
  - Максимальний горизонт — 20 років від поточного місяця;
  - Сьогоднішній день виділений рамкою/обводкою;
  - Архівовані кредити НЕ відображаються.
- **FR-CAL-3.** Кольори кредитів:
  - Палітра — 10 контрастних кольорів (індекси 1–10);
  - При **створенні** кредиту `colorIndex` призначається автоматично як `max(існуючих colorIndex активних кредитів) + 1`. Якщо результат > 10 → по колу (`((max) % 10) + 1`). Значення 0 у моделі означає «не призначено» і **замінюється на реальний індекс при save**; жоден збережений кредит не повинен мати `colorIndex = 0`;
  - `colorIndex` зберігається у `Loan` (п. 6.2) для консистентності кольору між сесіями.
- **FR-CAL-4.** Мітки на днях:
  - Кожен плановий платіж активного кредиту → кольоровий кружечок кольору кредиту (FR-CAL-3);
  - Стан мітки: **зелена галочка** = оплачено; **колір кредиту** = майбутній; **оранжевий** = прострочено;
  - Максимум **3 мітки** на одному дні; якщо більше → «+N» поряд (наприклад: 3 кружечки + «+2»).
- **FR-CAL-5.** Тап на день:
  - Порожній день (немає платежів активних кредитів) → ігнорується;
  - 1 платіж → одразу відкриваються деталі цього кредиту;
  - Кілька платежів → bottom sheet зі списком: назва кредиту + сума + статус (Оплачено / Майбутній / Прострочено). Тап на рядок → деталі кредиту.
- **FR-CAL-6.** Легенда під сіткою (два рядки):
  - Рядок статусів: 🟢 Оплачено · 🔵 Майбутній · 🟠 Прострочено;
  - Рядок кредитів: кольоровий кружечок + назва для кожного активного кредиту.
- **FR-CAL-7.** Список платежів під легендою:
  - Заголовок: назва **поточного** календарного місяця великими літерами (наприклад «ВЕРЕСЕНЬ»);
  - Вміст: усі платежі поточного місяця (не обраної пари!) — назва кредиту + сума + статус;
  - Список не згортається; усі рядки видно одразу;
  - При гортанні сітки до інших місяців список **не змінюється** — завжди поточний місяць.

### 3.15 Прогноз закриття кредитів (FR-FORECAST)

- **FR-FORECAST-1.** Блок прогнозу на екрані деталей кредиту (FR-DET-5):

  | Умова | Що показувати |
  |---|---|
  | Стратегія обрана АБО (кредит один + бюджет > min) **і** N > 0 | «Завдяки стратегії ви закриєте цей кредит раніше на N місяців» + рядок «За стратегією: [дата] · За графіком: [дата]» |
  | Стратегія обрана АБО (кредит один + бюджет > min) **і** N = 0 | Тільки «За графіком: [дата]» — без рядка порівняння |
  | Кредит один, стратегії немає, бюджету немає | Тільки «За графіком: [дата]» |
  | Кредитів > 1, стратегії немає | Банер «Оберіть стратегію, щоб закрити кредит раніше» (посилання на «План»). Дати не показуємо |

  Якщо по цьому кредиту є хоча б 1 прострочений платіж → додаткове попередження «Є прострочення, прогноз може бути неточним».

- **FR-FORECAST-2.** Попередження при фіксації платежу (обчислюється ДО збереження, у ViewModel):
  - `prevMonths` — кількість місяців до закриття цього кредиту **до** внесення нової суми (п. 4.7);
  - `newMonths` — кількість місяців після внесення;
  - **Якщо внесена сума < мінімального платежу** (недоплата): тривожний alert «Термін погашення збільшився на N місяців», де N = `newMonths − prevMonths`. Кнопка «Зрозуміло» → платіж зберігається;
  - **Якщо внесена сума ≥ мінімального АЛЕ < рекомендованого** (і рекомендований > мінімального): мотиваційний alert «Якщо внести рекомендовану суму ([sum] ₴), закриєте кредит раніше на N місяців». Кнопка «Зрозуміло» → платіж зберігається;
  - Якщо N = 0 для тривожного або мотиваційного alert — alert не показується;
  - Якщо внесено ≥ рекомендованого (або рекомендованого немає і ≥ мінімального) → alert не показується.

- **FR-FORECAST-3.** Тригери перерахунку — прогноз оновлюється після:
  - будь-якого платежу (плановий, позаплановий, переплата, недоплата);
  - редагування / додавання / видалення / архівації / розархівації кредиту;
  - зміни бюджету або стратегії.
  Прогноз обчислюється on-the-fly, не кешується в БД.

- **FR-FORECAST-4.** Дата закриття на екрані «Загальний борг» — відповідно до FR-DEBT-3.

- **FR-FORECAST-5.** Дата закриття на екрані «План» — відповідно до оновленого FR-STRAT-8.

- **FR-FORECAST-6.** Формат дати — відповідно до п. 4.7.

## 4. Бізнес-логіка розрахунків

> Усі розрахунки — Decimal (не Float/Double), округлення до копійок стандартне математичне (half-up), точність 2 знаки.

### 4.1 Ануїтетний платіж (режим «Я знаю ставку»)

```
i = річна_ставка / 12 / 100          — місячна ставка
A = S × i / (1 − (1 + i)^(−n))       — щомісячний платіж
```
де `S` — сума кредиту (залишок), `n` — кількість платежів.
Якщо ставка = 0%: `A = S / n`.

Розбивка кожного платежу:
```
відсотки_k = залишок_(k−1) × i
тіло_k     = A − відсотки_k
залишок_k  = залишок_(k−1) − тіло_k
```

### 4.2 Коригування останнього платежу

Останній платіж = `залишок_(n−1) + відсотки_n` (а не A), щоб `залишок_n = 0,00` рівно.

### 4.3 Розрахунок ставки (режим «Я знаю суму платежу»)

Дано: S, n, A. Знайти річну ставку.
- Якщо `A × n = S` (з точністю до копійок) → ставка = 0% (розстрочка). Допустима похибка — не більше `n × 0,01` грн (накопичена похибка округлення).
- Інакше — чисельний підбір місячної ставки `i` (бісекція), точність до 0,0001% річних. Річна ставка = `i × 12 × 100`.
- Якщо `A × n < S` (платіж замалий, рішення не існує) — повідомлення про некоректні дані.

### 4.4 Перерахунок після дострокового/зміненого платежу

Тригери: позаплановий платіж, переплата/недоплата, редагування/видалення платежу з історії, редагування кредиту.

Алгоритм:
1. Взяти фактичну історію платежів (у хронологічному порядку) і перерахувати залишок на поточний момент — **від `initialAmount` через всі `ActualPayment`**;
2. Побудувати новий графік від наступної планової дати з **оригінальним `paymentDay`** (не з числа clamped-дати):
   - сума платежу A **не змінюється** (крім редагування кредиту — тоді A перераховується);
   - кількість платежів перераховується ітеративно; при великій переплаті вона зменшується, при малій — лишається тією самою (зменшується лише останній платіж);
   - останній платіж коригується (п. 4.2);
3. Перепланувати нотифікації (від реальної наступної дати);
4. Перебудувати план стратегії (від поточного залишку, не від початкової суми).

### 4.5 Дати платежів

- День платежу = число дати першого платежу (`paymentDay`, зберігається окремо).
- Якщо `paymentDay > кількості днів у місяці` → платіж призначається на **останній день місяця**. При цьому `paymentDay` **не змінюється** — він залишається оригінальним значенням і застосовується до наступних місяців (де може бути достатньо днів).
- Всі дати — локальна таймзона пристрою, без UTC-перетворень. Порівняння дат — на рівні календарного дня.

### 4.6 Ефект стратегії

1. Базовий сценарій: усі кредити гасяться лише обов'язковими платежами → кількість місяців до закриття всіх кредитів `M0`;
2. Сценарій зі стратегією: щомісяця вільний залишок бюджету йде додатковим платежем на пріоритетний кредит. Після закриття кредиту його звільнений обов'язковий платіж **стає доступним у наступному місяці** і додається до вільного залишку («ефект снігової кулі»). Також у місяці закриття у поточний бюджет додається сума переплати (фактичний останній платіж < стандартного місячного);
3. Ефект = `M0 − M1` місяців (показується в UI).

### 4.7 Розрахунок дати закриття кредиту / всіх кредитів

**Базова дата відліку** — перший день наступного місяця від поточної дати (умовно «наступний платіжний цикл»).

**За графіком (один кредит):**
`schedule.last?.date` — дата останнього платежу у поточному розрахованому графіку.

**За стратегією (один конкретний кредит):**
Розширена симуляція `LoanCalculator.simulateToClosePerLoan`:
- аналог `simulateToClose`, але повертає `[UUID: Int]` — кількість місяців до закриття кожного кредиту з урахуванням ланцюжка звільнених платежів («ефект снігової кулі»);
- дата закриття кредиту `i` = baseDate + `months[i]` календарних місяців.

**За стратегією (всі кредити):**
Дата = baseDate + `max(months.values)` — коли закривається останній кредит.

**Один кредит без стратегії і з бюджетом > min:**
Симуляція з `extraBudget = budget − minPayment`, спрямованого на єдиний кредит.

**Формат дати (для всіх варіантів):**
«6 лютого 2028 року» — день + місяць у родовому відмінку + рік.
Місяці у родовому відмінку: січня, лютого, березня, квітня, травня, червня, липня, серпня, вересня, жовтня, листопада, грудня.

## 5. Нефункціональні вимоги

- **NFR-1.** Дані зберігаються тільки локально; жодних мережевих запитів у v1.
- **NFR-2.** Робота офлайн — повна.
- **NFR-3.** Час генерації/перерахунку графіка для кредиту на 360 платежів — < 1 сек. Головний екран — O(N) обчислень, де N = кількість кредитів (не O(N log N)).
- **NFR-4.** Світла тема (темна — v1.1).
- **NFR-5.** Орієнтація — портретна.
- **NFR-6.** Числовий формат: пробіл (non-breaking space) між тисячами, кома для копійок: «1 425,34 ₴». Поля вводу сум — аналогічно. Поле ставки — тільки нормалізація десяткового роздільника (без групування тисяч).

### 6.2 Модель даних (CloudKit-ready)

Вимоги сумісності з CloudKit для безшовної міграції у v1.1:
- без `@Attribute(.unique)`;
- усі relationships — optional;
- усі поля мають дефолтні значення або optional;
- ідентифікатори — UUID.

```
Loan
- id: UUID
- name: String = ""
- initialAmount: Decimal = 0        // початкова сума/залишок при додаванні
- annualRate: Decimal = 0           // % річних (розрахована або введена)
- monthlyPayment: Decimal = 0       // незмінна сума щомісячного платежу
- totalPlannedPayments: Int = 0     // оригінальна кількість платежів при створенні
- firstPaymentDate: Date = .now     // незмінна; задає paymentDay для всього графіка
- paymentDay: Int = 1               // 1–31; витягується з firstPaymentDate при створенні
- createdAt: Date = .now
- isArchived: Bool = false
- archivedAt: Date?
- manualPriority: Int = 0           // для стратегії «Свій порядок»
- colorIndex: Int = 0               // 1–10, колір у календарі; 0 = не призначено (замінюється при save)
- payments: [Payment]?              // relationship

Payment
- id: UUID
- loan: Loan?                       // relationship
- plannedDate: Date?                // nil для позапланових
- plannedAmount: Decimal = 0
- actualDate: Date?
- actualAmount: Decimal = 0
- isExtra: Bool = false             // позаплановий
- principalPart: Decimal = 0       // частка тіла (snapshot на момент внесення)
- interestPart: Decimal = 0        // частка відсотків (snapshot)

AppSettings (singleton-запис)
- id: UUID
- monthlyBudget: Decimal?           // nil = не задано
- strategy: String = "none"         // none | avalanche | snowball | manual
- notifyDayOf: Bool = true
- notify1DayBefore: Bool = true
- notify3DaysBefore: Bool = false
- onboardingCompleted: Bool = false
```

> **Single source of truth:** графік майбутніх платежів обчислюється on-the-fly з параметрів кредиту та фактичної історії. У БД зберігаються тільки фактичні платежі. Поточний залишок = `LoanCalculator.balance(from: initialAmount, ...)` — завжди від початкової суми через всю послідовність платежів.

### 6.3 Архітектура

- **MVVM:** View (SwiftUI) → ViewModel (`@Observable`) → Services → `LoanCalculator` / `StrategyPlanner`;
- **`LoanCalculator`** — чиста логіка (ануїтет, IRR, перерахунок, дати, ефект стратегії) без залежностей від UI/БД. Додатково: `Loan.sortedActualPayments()` і `Loan.currentBalance()` — спільні хелпери; `simulateToClosePerLoan` — per-loan дати закриття (п. 4.7);
- **`StrategyPlanner`** — побудова плану погашення (рекомендації, savedMonths);
- **`NotificationScheduler`** — планування нотифікацій. `rescheduleAllFromContext(_:)` — єдина точка входу для перепланування від `ModelContext`;
- **`HomeViewModel.buildScheduleMap(for:)`** — обчислює графіки всіх кредитів за один O(N) прохід.
